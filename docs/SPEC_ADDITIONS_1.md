# תוספת 1 למפרט הדגם

גרסה: 1.1 · 2026-11-03

ארבע תוספות ל-`docs/PROTOTYPE_SPEC.md`. יש לשלב אותן במפרט עצמו (בסעיפים המתאימים) ולעדכן את סדר השלבים כמפורט בסוף.

---

## א. סטטוס קשר (לקוח) וחסמים (תיק)

- **Client.contactStatus**: קוד מרשימה הניתנת להגדרה (LookupOption, רשימה חדשה `CONTACT_STATUS`).
  ערכי ברירת מחדל: פעיל, ממתין לתגובת הלקוח, לא זמין, הסתיים הטיפול.
  מוצג בכרטיס הלקוח וברשימת הלקוחות, עם סינון.
- **Case.blockers**: טקסט חופשי (אופציונלי), "מה עוצר את התיק כרגע".
  מוצג בלשונית "סקירה" בדף התיק, בולט אם לא ריק, ובלוח הבקרה כמספר "תיקים עם חסם".
- עריכה: מנהלת בלבד, עם נעילה אופטימית ו-AuditEvent כמו שאר עריכת התיק.

## ב. מודול החלטות

### ישות חדשה: Decision
| שדה | הערה |
| --- | --- |
| caseId | חובה |
| court | מרשימת הערכאות (LookupOption) |
| proceedingNumber | מספר הליך (ברירת מחדל: courtCaseNumber של התיק) |
| decisionDate | `YYYY-MM-DD`, חובה |
| title | תיאור קצר, למשל "החלטה בבקשה למזונות זמניים" |
| operativeText | הסעיף האופרטיבי (טקסט) |
| pageRef | עמוד וסעיף (טקסט, אופציונלי) |
| serviceDate | תאריך המצאה (אופציונלי) |
| serviceEvidence | אסמכתת המצאה: תיאור טקסט, ובשלב 4 ואילך גם קובץ (Document) |
| obligation | מה צריך לבצע (טקסט) |
| reviewStatus | `PENDING` / `REVIEWED` (נבדקה ע"י עו"ד) |
| sourceDocumentId | המסמך המקורי (אופציונלי, משלב 4) |
| inboxItemId | אם נוצרה מפריט חומר חדש (אופציונלי) |
| version, deletedAt, deletedById | כרגיל |

### כללים
- **ההחלטה היא מקור המועדים.** השדות decisionDate ו-serviceDate עוברים מ-Deadline אל Decision. ל-Deadline נוסף `decisionId` (אופציונלי). מועד שנוצר מהחלטה מציג את תאריכיה מתוכה.
- מתוך החלטה: "יצירת מועד" ו"יצירת משימה". השיוך לתיק, ההוראה (obligation) והקישור להחלטה מועתקים. אפשר כמה מועדים וכמה משימות להחלטה אחת.
- **המערכת לא מחשבת מועדים משפטיים.** את תאריך המועד מזינים ידנית, והוא נוצר במצב "ממתין לאימות". מתחת לשדה מוצג: "יש לחשב לפי ההחלטה, תאריך ההמצאה והכללים החלים, ולאשר."
- יצירת משימה מהחלטה אינה מסמנת את החובה כבוצעה.
- הרשאות: מנהלת יוצרת, עורכת ומסמנת "נבדקה". עובד רואה החלטות בתיקים שלו, ויכול ליצור החלטה במצב PENDING בתיק שלו.

### מסכים
- לשונית **"החלטות"** בדף התיק: רשימה לפי תאריך החלטה, חדש למעלה, עם תג "לא נבדקה" ומספר המועדים והמשימות שנוצרו.
- דף החלטה: כל השדות, המועדים והמשימות המקושרים, היסטוריה.
- מסך כללי **`/decisions`** בתפריט: כל ההחלטות שהמשתמש מורשה לראות, עם סינון לפי "לא נבדקה" ולפי ערכאה.
- מפריט חומר חדש מסוג "החלטת בית משפט": כפתור "יצירת החלטה מהפריט".

### נתוני דמה
- 12 החלטות ב-8 תיקים. חלקן עם מועדים ומשימות מקושרים, 4 לא נבדקו.

## ג. ייצוא רשומות (CSV)

- מסך **`/settings/export`**, למנהלת בלבד.
- ייצוא של: לקוחות, תיקים, משימות, מועדים, החלטות, חומר חדש (בלי קבצים), ורשימת מסמכים (מטא-דאטה בלבד).
- כל ייצוא הוא קובץ CSV נפרד, או ZIP עם כולם.
- **קידוד UTF-8 עם BOM**, כדי שעברית תיפתח נכון ב-Excel. כותרות העמודות בעברית. תאריכים בפורמט `YYYY-MM-DD`.
- מסומן בבירור: "הייצוא אינו כולל את הקבצים עצמם ואינו תחליף לגיבוי."
- כל ייצוא כותב AuditEvent: מי, מתי, אילו טבלאות, כמה שורות.
- הייצוא נעשה דרך שירות עם בדיקת הרשאה, לא ישירות מ-Prisma.

## ד. קליטת מסמכים חדשים מ-Dropbox (דמה)

### הזרימה
1. קובץ חדש "מופיע" בתיקיית Dropbox (בדגם: כפתור למנהלת במסך החיבורים, "סימולציה: קובץ חדש הגיע ל-Dropbox", עם בחירה מתוך כמה קבצי דמה מוכנים. מסומן "דמה").
2. ה-DropboxAdapter מחזיר את הקובץ: שם, נתיב, מזהה, גרסה.
3. **ניסיון זיהוי** (בדגם: לפי שם הקובץ והנתיב):
   - מספר הליך או מספר פנימי של תיק מופיע בשם או בנתיב → הצעת שיוך לתיק הזה.
   - התיקייה ממופה לתיק (`Case.dropboxFolderPath`) → הצעת שיוך לתיק.
   - מילים כמו "החלטה" בשם הקובץ → הצעת סוג "החלטת בית משפט".
4. נוצר **פריט חומר חדש** עם `source = DROPBOX`, מזהה הקובץ והגרסה, ושדה `suggestedCaseId` עם `matchReason` (טקסט: "מספר ההליך מופיע בשם הקובץ").
   - אם יש התאמה אחת ברורה, הפריט מוצג עם "הצעה: תיק X – אישור / שינוי".
   - אם אין התאמה, או יש יותר מאחת, הפריט נכנס ל"לשיוך". **זה תור הבדיקה, ואין לבנות תור נפרד.**
5. מהפריט: "יצירת משימה", "יצירת החלטה" (אם הסוג הוא החלטה), "יצירת מועד".
6. **מניעת כפילויות:** אותו מזהה קובץ ואותה גרסה לא נקלטים פעמיים.
7. שדה `readStatus` לפריט: `NAME_ONLY` (זוהה לפי שם בלבד) / `TEXT_READ` / `UNREADABLE`. בדגם תמיד `NAME_ONLY`, ומוצג בתג: "זוהה לפי שם הקובץ בלבד – התוכן לא נקרא".

### מחוץ לדגם
- קריאת התוכן בפועל (חילוץ טקסט, OCR לסריקות) וזיהוי לפי התוכן. בגרסה האמיתית: שירות OCR שייבחר אחרי בדיקת עלות ופרטיות.
- מעקב אוטומטי אחר שינויים ב-Dropbox (webhook או סריקה מתוזמנת).
