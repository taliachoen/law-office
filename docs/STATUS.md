# מצב הפרויקט

עודכן: 2026-11-02

## שלב 1 – שלד: הושלם, ממתין לאישור

### מה נבנה
- Next.js 16 (App Router) + TypeScript strict + Tailwind 4, עברית ו-RTL, גופן Heebo.
- Prisma 7.10.1 + SQLite (`better-sqlite3`), סכמה מלאה לפי סעיף 5 במפרט, migration `init`.
- seed בעברית: 3 משתמשים, 12 לקוחות, 15 תיקים, 25 משימות, 10 חומר חדש, 20 מועדים (18 עתידיים + 2 שעברו), 30 מיילים. בלי קבצים (שלב 4).
- `src/server`: `db`, `auth/current-user` + בורר משתמשים (cookie), `policy` (can / authorize / caseScope / clientScope / inboxScope), `audit` (כותב רק בתוך טרנזקציה), `errors`, `services/dashboard`.
- `src/shared`: `constants` (ערכים ותוויות בעברית), `dates` (Asia/Jerusalem), `schemas` (zod).
- layout עם תפריט וסרגל עליון, לוח בקרה זמני עם ספירות, מסך שגיאה.
- התפריט כולל רק "לוח בקרה", כי מסכים שלא נבנו לא מופיעים (אין כפתורים מתים).

### מה נבדק בפועל
- `npm run typecheck`, `npm run lint`: עוברים.
- `npm test`: 17 בדיקות עוברות (הרשאות, scope, ספירות לוח הבקרה לפי משתמש, audit בטרנזקציה כולל rollback).
- `npm run build`: עובר.
- `npm run dev`: הדף `/` מחזיר 200, `lang="he" dir="rtl"`, ספירות שונות לכל משתמש, cookie לא תקין חוזר למנהלת.

### מה לא נבדק
- לא נבדק בדפדפן אמיתי: מראה, גופן, תפריט הטלפון, החלפת משתמש בלחיצה (נבדק רק ה-HTML בשרת).
- `npm run db:reset` לא הורץ על ידי Claude: Prisma חוסם `migrate reset` מסוכן כשהוא מורץ על ידי סוכן AI ודורש הסכמה מפורשת. ה-seed הורץ על מסד ריק בעזרת `prisma db seed`.

### החלטות והערות
- `AuditEvent` קיבל שדה `caseId` (תוספת למפרט) כדי שלשונית "היסטוריה" בתיק תוכל לשלוף אירועים.
- `orgId`, `deletedById`, `verifiedById`, `viewedById` הם מחרוזות בלי מפתח זר.
- חומר חדש בלי תיק: עובד רואה רק מה שהוסיף בעצמו.
- TypeScript 5.9 ו-ESLint 9 (לא הגרסאות האחרונות), כי typescript-eslint תומך עד TS 6.0.
- npm 11 חוסם install scripts כברירת מחדל; אושרו רק `better-sqlite3`, `prisma`, `@prisma/engines`, `esbuild`.
- `AGENTS.md` נוצר אוטומטית על ידי `next dev`.

### שינוי תכנוני: רשימות הניתנות להגדרה (אחרי שלב 1)
- סוגי תיקים, ערכאות וסוגי חומר חדש עברו מ-`constants.ts` לטבלה `LookupOption` (לפי `orgId`). הטבלאות העסקיות שומרות את ה-`code`, והתווית נשלפת מהטבלה.
- ערך שבשימוש מכבים (`active=false`) ולא מוחקים. `assertValidOption` בשירות `lookups` בודק קוד בשמירה (zod לא יכול).
- ברירות מחדל של דיני משפחה: `src/shared/lookup-defaults.ts`, נטענות ב-seed.
- נשארו קבועים בקוד: תפקידים, סטטוס תיק, מצבי משימה, עדיפות, סוג מועד, אימות, מקור מסמך, ספקי חיבור.
- נבדק: typecheck, lint, 23 בדיקות; seed על מסד זמני (8/5/5 ערכים, אפס קודים יתומים).
- **מסד הפיתוח המקומי עדיין בלי ערכי הרשימות.** יש להריץ `npm run db:reset`.
- עוד אין UI לניהול הרשימות (ייבנה עם מסך ההגדרות, מנהלת בלבד), כדי לא להציג כפתורים מתים.

## שלב 2 – לקוחות ותיקים: נבנה, ממתין לבדיקה בדפדפן ולאישור

### מה נבנה
- shadcn/ui (סגנון base-nova, RTL) עם Heebo כגופן; Dialog / AlertDialog / Table / Button וכו'. שדות select הם `<select>` רגיל של הדפדפן (נשלח ב-FormData, נגיש, נוח בטלפון).
- שירותים: `clients`, `cases`, `users`. הרשאה בכל פעולה, AuditEvent באותה טרנזקציה, נעילה אופטימית בעדכון תיק.
- מסכים: `/clients`, `/clients/[id]`, `/cases`, `/cases/[id]` (לשוניות סקירה והיסטוריה). חיפוש וסינון בטופס GET. טבלה בדסקטופ וכרטיסים בטלפון.
- פעולות (מנהלת בלבד): יצירה ועריכה של לקוח ותיק בחלונית, הוספה והסרה של איש קשר, מחיקת לקוח לסל (חסומה כשיש תיק שאינו סגור), שיוך עובדים לתיק.
- ניסיון גישה ישירה לתיק או ללקוח של אחר מציג "אין הרשאה" בלי הנתונים.
- לוח הבקרה: הכרטיסים "לקוחות" ו"תיקים פעילים" לחיצים.

### מה נבדק בפועל
- typecheck, lint, build: עוברים. 39 בדיקות (16 חדשות לשירותי לקוחות ותיקים: הרשאות עובד, חיפוש, מספר פנימי, נעילה אופטימית, שיוך, מחיקה רכה, audit).
- דפים נבדקו ב-HTTP מול מסד זמני עם seed עדכני, בכל משתמש: מנהלת רואה 12 לקוחות ו-15 תיקים, עובד א' 7 ו-7 בלי כפתורי יצירה; תיק ולקוח של אחר מחזירים "אין הרשאה" (גם בלשונית ההיסטוריה); תיק לא קיים מחזיר 404.

### מה לא נבדק
- **לא נבדק בדפדפן:** פתיחת חלוניות, שליחת טפסים (Server Actions), הודעות שגיאה בשדות, חלונית מחיקה (מיקוד על ביטול, Esc), נעילת כפתור בזמן שליחה, תצוגת טלפון. הבדיקות כיסו את השירותים שמאחוריהם.
- מחיקת תיק לסל לא נבנתה (הסל כולו בשלב 6).

### הערות
- מסד הפיתוח המקומי נמצא בלי ערכי רשימות (`LookupOption` ריק), ולכן סוגי התיקים יוצגו כקודים והטופס לא יאפשר לבחור סוג. יש להריץ `npm run db:reset`.
- אין עימוד ברשימות (בדגם יש 12-15 רשומות).
- הבדיקות רצות קובץ אחר קובץ (`fileParallelism: false`), כי כולן משתמשות בקובץ SQLite אחד.
- החבילה `cn` (שה-CLI של shadcn התקין, פורסמה ב-2026-11-02) הוסרה והוחלפה בפונקציה מקומית ב-`src/lib/utils.ts` מעל `clsx` ו-`tailwind-merge`. החלטה: לא להחזיק חבילה חדשה במערכת שתחזיק מידע חסוי.
- **לתיקון בשלב 6:** "אין הרשאה" מוחזר כדף עם סטטוס HTTP 200. יש להחזיר 403 או 404 (404 מונע גם הסקה שהתיק קיים). חל על `/cases/[id]`, `/clients/[id]` ועל `/api/files/[id]` כשייבנה.
- תלויות שה-CLI של shadcn התקין ופורסמו לאחרונה: `lucide-react` 1.66.0 (2026-10-31), `shadcn` 4.23.0 (2026-10-27), `@base-ui/react` 1.9.0 (2026-10-09). מומלץ לבדוק ולהצמיד גרסאות לפני פריסה אמיתית.

## שלב 3 – משימות: נבנה, ממתין לבדיקה בדפדפן ולאישור

### מה נבנה
- מכונת המצבים (סעיף 7) כפונקציות טהורות ב-`src/shared/task-flow.ts`: השירות משתמש בה לאכיפה והממשק להצגת כפתורים, כך שהם לא יכולים להיסטות זה מזה.
- שירות `tasks`: יצירה, רשימות לפי לשוניות, פרטי משימה עם ציר זמן, כל המעברים, מחיקה לסל ושחזור. סדר הבדיקות בכל מעבר: הרשאה, גרסה, חוקיות המעבר, חובת טקסט. TaskEvent ו-AuditEvent נכתבים באותה טרנזקציה.
- מסכים: `/tasks` (פתוחות, המשימות שלי, ממתינות לבדיקה, הושלמו; סינון "באיחור"), `/tasks/[id]`, לשונית "משימות" בדף התיק, `/trash` (משימות בלבד בשלב הזה).
- צבעים לפי המפרט: כתום להחזרה לתיקון, ירוק לסיום, אדום למחיקה (חלונית אישור עם מיקוד על "ביטול").
- לוח הבקרה: כרטיסי המשימות לחיצים. הקישור "סל מחזור" בתפריט מוצג למנהלת בלבד.

### מה נבדק בפועל
- typecheck ו-lint עוברים. 68 בדיקות (29 חדשות למשימות): טבלת המעברים כתובה ידנית מול הקוד, כל פקודה מול כל מצב, מי רשאי ומי לא, הגשה בלי הערה, החזרה בלי הערה, סיום בלי סיכום, פתיחה מחדש בלי סיבה, מעברים לא חוקיים בשליחה ישירה, גרסה ישנה (כולל שתי פעולות במקביל), מחיקה ושחזור מכל אחד מחמשת המצבים, עובד שאינו בתיק.
- דפים נבדקו ב-HTTP מול שרת הפיתוח הקיים (קריאה בלבד): 19 פתוחות, 2 באיחור, 5 לבדיקה ו-6 שהושלמו למנהלת; עובד א' רואה 13 פתוחות; הכפתורים בדף משימה משתנים לפי תפקיד ומצב; משימה בתיק של אחר מחזירה "אין הרשאה"; הסל חסום לעובד.

### מה לא נבדק
- **לא נבדק בדפדפן:** שליחת הטפסים והחלוניות (Server Actions), כולל נעילת כפתור, הודעות שגיאה, Esc ומיקוד בחלונית המחיקה. השירותים שמאחוריהם נבדקו בבדיקות.
- `npm run build` לא הורץ בשלב הזה (שרת פיתוח אחר רץ על אותה תיקייה).

### החלטות והערות
- **הגשה לבדיקה דורשת הערת מענה.** המפרט מאפשר "קובץ חדש או הערה"; האפשרות של קובץ תתווסף בשלב 4 (מסמכים). אז גם יתווספו "קבצים מצורפים" לדף המשימה ו"אפשר לצרף גרסה" בהחזרה לתיקון.
- המנהלת רשאית טכנית להגיש משימה (טבלת ההרשאות אומרת "כן"), אבל הכפתור מוצג רק לעובד המוקצה.
- אין עריכה של כותרת, הוראות, עדיפות ומועד של משימה קיימת: המפרט לא מגדיר אותה. אפשר להוסיף אם נרצה.
- פתיחה מחדש מרוקנת את `completionSummary` (הסיכום הישן נשאר בציר הזמן). פתיחה מחדש בלי עובד מחזירה ל-OPEN ומנקה את העובד.
- משימה חדשה אסורה בתיק סגור. העברה לעובד אפשרית רק לעובד פעיל שמשויך לתיק.
- מחיקת משימה לא מוחקת את המסמכים שלה (יבדק במלואו בשלב 4).
